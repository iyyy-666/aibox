# AIBox Studio 产品与技术架构

版本：0.1（架构基线）  
日期：2026-10-08

## 1. 产品定义

AIBox Studio 是运行在 RK3588 Linux 桌面系统上的离线学生编程教学平台。
它不是通用 IDE，也不是功能演示程序的代码外壳，而是把教材、受限 Python
执行环境、`aibox` 学生 SDK、实时实验效果和实验箱设备组织成一个完整产品。

### 1.1 用户与场景

- 用户：职业院校、技工院校中无编程基础或基础较弱的学生。
- 使用方式：一台实验箱对应一名学生，本地单机使用。
- 网络条件：断网时全部核心实验必须可运行。
- 课程范围：教材中的 56 个基础实验；第一版不规划通用物体目标检测实验。
- 第一版不包含：登录、教师端、成绩、自动判题、云端同步、课程编辑器。

### 1.2 成功标准

学生能够只通过“选择实验、修改代码、运行、观察、停止”完成教材实验，
且不需要理解 Linux、USB、串口、GPIO、驱动、ROS 或模型部署。

## 2. 界面信息架构

主窗口使用四区工作台，不使用营销首页。

```text
┌──────────────┬────────────────────────┬──────────────────┐
│ 实验课程导航 │ 学生代码编辑区         │ 实验效果显示区   │
│ 章节/实验    │ Python高亮、行号        │ 视频/雷达/状态   │
│ 实验说明     │ 运行、停止、保存、还原 │ 识别结果/动作    │
├──────────────┴────────────────────────┴──────────────────┤
│ 运行结果：标准输出、中文提示、错误定位、运行状态        │
└─────────────────────────────────────────────────────────┘
```

### 2.1 左侧课程导航

- 按篇、章、实验三级组织 56 个实验。
- 显示当前实验目的、准备事项、接口提示和小练习。
- 切换实验前，如程序正在运行，必须先停止并确认设备已释放。
- 不显示完成率、分数和排名。

### 2.2 中间代码编辑区

- Python 语法高亮、行号、当前行、括号匹配、撤销和重做。
- 固定提供运行、停止、保存、恢复模板四个命令。
- 保存只写入学生工作目录，不修改课程原始模板。
- 错误时定位到具体行，但不展示底层驱动堆栈。

### 2.3 右侧实验效果区

效果面板由实验清单选择，而不是由学生代码任意创建窗口：

- `camera`：实时画面、识别框、识别文字。
- `radar`：A1M8 扫描图、区域距离、变化状态。
- `arm`：当前动作、忙碌/停止状态、安全提示。
- `voice`：录音状态、识别文字、播放状态。
- `assistant`：提问和本地模型回答。
- `text`：不需要专用可视化的基础实验。

### 2.4 底部运行结果

- 显示 `print()` 输出、开始/结束时间和中文状态。
- 学生错误显示“第 N 行：问题和修改建议”。
- 设备错误显示“摄像头未连接”“机械臂正在被功能演示占用”等产品语言。
- 原始异常和诊断详情只进入本地维护日志。

## 3. 分层架构

```text
AIBox Studio (PySide6)
  │
  ├─ Course Engine：课程清单、模板、教材说明
  ├─ Editor：编辑、保存、错误定位
  ├─ Effect Panels：视频、雷达、机械臂、语音、AI
  └─ Runner Manager：校验、启动、停止、输出
          │
          ▼
Student Runner（低权限隔离进程）
  ├─ 受限 Python 解释器
  └─ aibox SDK（学生公开 API / 本地 RPC 客户端）
          │ Unix Domain Socket + 会话令牌
          ▼
AIBox Device Service（统一设备服务）
  ├─ Resource Manager：跨应用设备互斥
  ├─ Session Manager：生命周期、取消、超时
  ├─ Model Manager：模型按需加载与回收
  ├─ Event Gateway：画面、雷达、识别和动作事件
  └─ Error Translator：底层错误到中文产品错误
          │
          ▼
Hardware Adapters
  ├─ ArmAdapter
  ├─ CameraAdapter / GimbalAdapter
  ├─ VisionAdapter / ModelBackend
  ├─ LidarAdapter
  ├─ AudioAdapter / ASR / TTS
  └─ LLMAdapter
          │
          ▼
串口、V4L2、ALSA、A1M8、RKNN/ONNX、真实设备
```

### 3.1 核心边界

1. UI 不直接访问硬件。
2. 学生进程不直接访问 `/dev`、模型文件或系统服务。
3. `aibox` 包只暴露教材 API，并通过 RPC 调用设备服务。
4. 设备服务是硬件状态和资源所有权的唯一事实来源。
5. 硬件适配器可以替换，教材 API 不随硬件型号变化。

## 4. 技术选型

### 4.1 推荐方案

| 领域 | 选择 | 说明 |
|---|---|---|
| 桌面 UI | PySide6 / Qt 6 | ARM Linux 成熟，与 Python 和现有算法一致 |
| 编辑器 | QPlainTextEdit + QSyntaxHighlighter | 第一版足够稳定，可控制依赖和授权 |
| 主业务 | Python 3.11 | 与教材一致，可复用当前功能演示资产 |
| 本地 IPC | Unix Domain Socket + JSON 消息 | 不开放网络端口，便于鉴权和进程隔离 |
| 视频 | 共享内存最新帧 + 元数据事件 | 避免 Base64/HTTP 带来的 CPU 和内存开销 |
| 雷达绘制 | QPainter | 本地高频绘制，依赖少 |
| 推理 | RKNN 优先，ONNX Runtime 后备 | 发挥 RK3588 NPU，同时保留模型兼容性 |
| 数据 | JSON 课程清单 + Python 模板 | 可版本控制、校验和离线更新 |
| 打包 | venv + 固定依赖 + systemd 服务 | 可重复部署和维护 |

### 4.2 不选 Electron 的原因

- RK3588 上内存与启动成本更高。
- 仍需单独 Python 后台控制设备，增加两套运行时和通信复杂度。
- 当前团队资产、算法和测试主要是 Python，Qt 的集成成本更低。

## 5. 进程与资源模型

### 5.1 进程组成

- `aibox-studio`：以 `ztl` 用户运行的桌面主程序。
- `aibox-runner`：每次运行创建的学生代码子进程。
- `aibox-device-service`：systemd 管理的本地设备服务，不运行学生代码。
- 模型 worker：由设备服务按需创建，退出实验后按策略保留或回收模型。

### 5.2 运行状态机

```text
IDLE -> VALIDATING -> STARTING -> RUNNING -> OBSERVING
  ^          │            │          │           │
  └──────── FAILED <──────┘          └─ STOPPING ┘
                                      │
                                      └─ IDLE / CLEANUP_FAILED
```

- `RUNNING`：学生顶层代码仍在执行。
- `OBSERVING`：代码已执行完，但 `camera.show()`、`lidar.show()` 或
  `hand.track()` 创建了持续效果；学生点击停止后结束。
- `COMPLETED` 不单列为持久状态；无持续资源时输出完成信息并回到 `IDLE`。

### 5.3 资源互斥

资源键至少包括：`camera`、`gimbal`、`robot`、`lidar`、`microphone`、
`speaker`、`asr`、`tts`、`llm`、`npu`。

一次运行在启动前声明所需能力并原子获取资源。若“功能演示”正在使用同一设备，
学生平台应提示退出功能演示，而不是抢占设备。两个软件最终都接入同一 Device
Service；迁移完成前使用同一跨进程锁文件兼容旧功能演示。

## 6. 学生代码安全

仅做 AST 白名单不是安全隔离。第一版采用四层防护：

1. **教学校验**：AST 检查并给出友好错误；禁止危险导入、危险内置函数和双下划线访问。
2. **进程隔离**：学生代码始终在独立进程运行，主界面不执行 `exec()`。
3. **操作系统隔离**：使用 `bubblewrap` 创建只读运行环境，取消网络命名空间，
   不绑定 `/dev`，仅开放临时目录、工作文件和 Device Service 套接字。
4. **资源限制**：`no_new_privs`、CPU/内存/进程数/文件大小/输出大小/运行时间限制。

### 6.1 第一版允许内容

- `from aibox import ...`
- `time`、`math`、`random`（按实验清单进一步收窄）
- 变量、字符串、数字、列表、字典、条件、有限循环、函数定义和 `print()`

### 6.2 禁止内容

- `os`、`sys`、`subprocess`、`socket`、`ctypes`、`importlib`、`pathlib`
- 文件读写、动态导入、`eval`、`exec`、`compile`、系统命令和网络
- 直接访问 USB、串口、GPIO、摄像头、麦克风和系统服务
- 无边界递归、后台子进程和无限输出

## 7. 错误处理

设备服务返回稳定错误码，UI 负责中文展示：

| 错误码 | 学生提示 |
|---|---|
| `DEVICE_NOT_FOUND` | 未找到所需设备，请检查连接。 |
| `RESOURCE_BUSY` | 设备正在被其他功能使用，请先退出该功能。 |
| `CAMERA_NO_FRAME` | 暂时没有读取到摄像头画面。 |
| `MODEL_LOAD_FAILED` | 识别功能启动失败，请重新打开实验。 |
| `ROBOT_BLOCKED` | 机械臂动作未完成，请清理障碍物后重试。 |
| `SPEECH_NOT_HEARD` | 没有听清，请靠近麦克风后重试。 |
| `RUN_TIMEOUT` | 程序运行时间过长，已安全停止。 |
| `CODE_NOT_ALLOWED` | 此实验不允许使用该模块或函数。 |

维护日志保存在 `/var/log/aibox/`，默认不在学生界面展示。

## 8. 课程包与版本

课程包由 `manifest.json`、实验清单、代码模板和说明文本组成。

- `course_version`：教材内容版本，例如 `1.0.0-rc1`。
- `sdk_compatibility`：支持的 SDK 范围，例如 `>=1.0,<2.0`。
- 实验使用稳定 ID，例如 `vision.color.01`，标题变化不改变 ID。
- 厂家课程目录只读；学生保存内容位于个人工作目录。
- 更新课程包前执行结构校验、API 校验和 56 个模板离线运行测试。

## 9. 部署布局

```text
/opt/aibox-studio/                 程序、SDK、内置课程
/opt/aibox-models/                 离线模型和标签
/etc/aibox-studio/                 设备与产品配置
/var/lib/aibox-studio/             状态、课程版本、迁移记录
/var/log/aibox/                    维护日志
/home/ztl/Documents/AIBoxStudio/   学生代码
/home/ztl/Desktop/AIBox学生编程平台.desktop
```

桌面同时保留“功能演示”和“AIBox学生编程平台”。安装包不得覆盖学生文件。
升级采用版本化目录、安装前备份、健康检查和失败回滚。

## 10. 质量与验收

### 10.1 自动化测试

- 公开 SDK 的参数、返回值、错误码和向后兼容测试。
- 56 个模板的语法、权限和模拟设备运行测试。
- Runner 超时、停止、崩溃、超量输出和沙箱逃逸测试。
- 设备资源冲突与异常释放测试。
- 模型缺失、设备断开、重复运行和快速切换测试。

### 10.2 实机验收

- 所有模板在断网状态下运行。
- 机械臂异常时停止按钮在 500 ms 内发出停止请求。
- 视觉画面稳定且退出后摄像头无占用。
- A1M8 连续运行 30 分钟无遗留线程或串口占用。
- 语音输入、TTS 和本地 AI 在无网络时可用。
- 学生代码无法读取 `/etc/shadow`、设备节点或启动网络连接。
- 连续切换实验 50 次，无遗留 runner 和设备句柄。

## 11. 分阶段实施

1. **架构与合同**：冻结 SDK 1.0、56 个实验清单、IPC 与错误码。
2. **桌面框架与模拟器**：完成 UI、课程加载、编辑器、Runner 和模拟 SDK。
3. **统一设备服务**：抽取现有功能演示的资源管理和适配器。
4. **机械臂与安全停止**：接入 Arm API，完成动作互斥与实机验收。
5. **视觉与模型**：接入 Camera、Vision、Face、Hand 和右侧实时画面。
6. **雷达、语音与AI**：接入 Lidar、ASR、TTS、本地大模型。
7. **56实验联调**：逐实验核对教材、模板、输出和效果面板。
8. **产品化交付**：安装、升级、恢复、日志、稳定性和学校验收。

## 12. 已确认的教材处理原则

1. 实验 34 至 42 按现有“按钮控制机械臂”能力制作差异化模板，包括直立、放平、抓取、搬运、夹爪张开/半开/闭合以及 6 个舵机微调。
2. 舵机高级实验可使用 PWM，但只能操作 1 至 6 号舵机，允许范围固定为 `800–2200`；SDK 与 Device Service 双重校验。
3. 实验 43 至 46 的语音控制命令只采用现有功能演示已经支持的命令，不扩展自由语义控制。
4. 实验 50 使用 `Voice.speak(text)`，通过实验箱声卡朗读学生在代码中填写的文字。
5. 摄像头不设置独立编程实验；学生只学习调用 `Camera().show()` 显示实时画面，设备打开与释放由平台管理。
6. 第一版不提供通用物体目标检测 API 或实验；雷达实验只调用封装后的 `Lidar` 接口，不教授串口与底层协议。

后续教材文字微调通过课程包补丁版本完成，不改变这些已经确认的产品边界。
