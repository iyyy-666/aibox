# 雷达扫描结果对齐与基准检测设计

## 目标

在 RK3588 上直接读取 Slamtec A1M8 原始扫描数据，使相同安装位置、相同环境下的点云几何与笔记本上位机一致：固定物体应出现在相同角度和近似距离，轮廓应可对应。由于雷达逐圈存在正常测距噪声，不要求两个设备逐点、逐帧完全相同。

雷达模块还应稳定完成无物块基准建立，在指定固定区域输出“固定位置存在物块”或“固定位置不存在物块”。“是否搬运”只记录人工确认，不自动控制机械臂。

## 已确认根因

A1M8 收到 `A5 20` 扫描命令后，实际返回以下 7 字节扫描响应描述头：

```text
A5 5A 05 00 00 40 81
```

描述头之后才是连续的 5 字节 legacy scan node。当前实现未消费描述头，直接将整个输入按 5 字节切分，因此节点边界偏移 2 字节。解析器会丢弃大量节点，通常无法识别完整旋转圈。这同时造成：

- RK3588 点云与笔记本上位机明显不同；
- 有效点数很少或不稳定；
- 无法持续产生完整扫描圈；
- “建立基准”从小容量队列取不到足够帧并超时。

RK3588 已正确识别 CP2102 设备，稳定路径为：

```text
/dev/serial/by-id/usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0
```

该路径当前指向 `/dev/ttyUSB1`。原始串口抓包能够获得描述头和后续扫描节点，因此目前没有证据表明 USB 驱动是主要问题。

## 方案选择

采用现有 Python 原始协议驱动，不引入 Slamtec C++ SDK，也不尝试在 ARM64 上运行 Windows 上位机。

原因：当前需求只使用 A1M8 标准扫描模式，协议响应已经通过真实设备抓包确认。修正解析器即可保持依赖和部署最轻量，并避免新增本地编译产物与跨进程桥接。若真实硬件验证后仍无法稳定获得标准节点，再单独评估官方 SDK，不能在本次修复中同时引入两套后端。

## 数据流与组件边界

```text
A1M8
  -> 串口字节流
  -> 扫描响应描述头校验
  -> 5 字节节点流自动对齐
  -> 完整旋转圈组帧
  -> 最近完整圈缓冲
  -> 点云显示 / 基准建立 / 实时检测
```

### 设备层

- 保持现有稳定设备路径发现逻辑，不硬编码 `/dev/ttyUSB0`。
- 打开串口前设置 DTR、RTS 和流控状态，避免进入模块时因控制线跳变影响电机。
- 每次启动只发送一次 `A5 20`。
- 精确读取并校验 7 字节响应描述头后，才进入节点读取状态。
- 退出模块时发送 `A5 25` 并关闭串口；模块运行期间不重复开关串口。

### 流解析层

- 使用有状态字节流解析器，不假设每次 `read()` 都落在节点边界。
- 合法节点必须同时满足起始位及其反码关系、角度校验位、有效角度范围和有效距离编码。
- 当前 5 字节窗口不合法时只丢弃一个字节，再检查下一窗口，以便在丢字节或混入异常字节后自动恢复对齐。
- 使用 scan-start 标志划分旋转圈。只在收到下一圈起始节点时提交上一完整圈。
- 启动时起始标志之前的残缺数据不作为一圈输出。

### 诊断指标

运行时维护并发送以下指标：

- 串口接收字节数/秒；
- 有效扫描点数/秒；
- 完整扫描圈数/秒；
- 最近一圈有效点数；
- 最近完整圈距当前时间；
- 描述头与流对齐错误状态。

指标用于判断问题位于设备、协议还是检测区域，不能用“雷达已连接”笼统代替数据有效性。

## 数据就绪与基准建立

- 后端保存一个有界的最近完整圈缓冲，容量至少覆盖基准所需 12 圈。
- 连续收到 5 圈有效完整扫描前，“建立基准”不可用，并显示 `有效扫描 X/5`。
- 完整圈需要达到合理的最小有效点数；空圈或明显残缺圈不计入就绪进度。
- 点击“建立基准”后使用 12 个完整圈，不再依赖当前容量为 3 的消费队列临时等待。
- 只选择配置检测区域内的数据。区域内没有足够有效点时，建立失败并明确提示“检测区域无有效点”。
- 将检测区域按角度分桶，每个角度桶使用 12 圈距离中位数作为无物块基准，以抑制正常测距抖动。

## 实时检测

每个完整圈执行一次比较：

1. 选取配置检测区域内的点；
2. 对齐到相同或邻近角度桶；
3. 计算距离变化超过阈值的桶比例；
4. 将缺失点比例和有效点比例作为辅助有效性指标；
5. 连续 3 圈达到变化阈值后输出“固定位置存在物块”；
6. 连续 3 圈恢复正常后输出“固定位置不存在物块”。

串口无数据、描述头错误、没有完整扫描圈或检测区域无有效点时，状态为“雷达数据无效”，不得输出“不存在物块”。关键距离阈值、变化比例、连续确认圈数、基准圈数和区域范围继续保持可配置。

## 检测区域

参考图中红圈仅用于说明目标位置，不是官方上位机数据的一部分。目标大致位于图中下方至左下区域，但不能直接把整个第三象限作为检测区域。

区域继续由以下参数定义：

- 最小角度；
- 最大角度；
- 最小距离；
- 最大距离。

初始参数只用于现场校准。修复点云后，根据物块实际出现的角度和距离收紧边界，再保存最终配置。检测区域以独立轮廓覆盖层显示，不修改原始点云颜色。

## 扫描画面

显示目标是让扫描结果便于和笔记本上位机直接对照，而不是复刻其 Windows 工具栏。

- 黑色背景，固定 `0-8 m` 量程；
- `0°` 位于正上方，`90°` 位于右侧，角度顺时针增加；
- 显示极坐标距离环、30°角度刻度和标签；
- 原始有效点使用青色；
- 显示当前扫描角度射线、扫描频率和 RPM；
- 不对点云进行插值、补点或几何平滑；
- WebSocket 传输可限流，但不得改变点的角度和距离，单圈抽样必须保证整体几何可辨认。

相同环境下的验收标准是主要墙面、物块和遮挡轮廓在两个画面中的角度与距离一致。允许点数、瞬时噪声和单点位置存在 A1M8 正常波动。

## 模块布局

- 雷达画布占据主要区域，保持正方形并完整显示 8 m 圆盘。
- 右侧固定显示连接状态、数据就绪、基准状态、检测状态、最终结果和诊断指标。
- 操作区固定显示“建立基准”“开始检测”“停止检测”“是否搬运”。
- 适配 RK3588 当前显示器，一屏完成主要操作，不依赖页面上下滚动。
- “是否搬运”只记录人工确认，不调用机械臂动作。

## 错误处理

用户可见错误必须区分：

- 没有发现雷达串口；
- 串口可打开但没有收到字节；
- 扫描响应描述头无效；
- 节点流无法对齐；
- 尚未形成完整扫描圈；
- 检测区域内没有有效点；
- 基准样本不足。

读取线程异常后应释放串口资源并报告原因。不得静默回退到模拟数据，也不得占用机械臂或云台串口。

## 测试与真实硬件验证

### 自动化测试

- 描述头被完整消费且验证字段正确；
- 描述头拆分在多次串口读取中仍可解析；
- 节点从任意读取边界进入均可解析；
- 前置垃圾字节、单字节丢失后能够重新对齐；
- 只输出完整旋转圈；
- 连续 5 圈前后数据就绪状态正确；
- 基准使用 12 圈并正确处理中位数；
- 无数据、无完整圈和区域无点返回不同错误；
- 前端角度坐标转换满足 0°上、90°右；
- 现有非雷达功能测试保持通过。

### RK3588 验证

1. 确认稳定串口路径解析到实际 CP2102 设备；
2. 进入模块后确认雷达持续旋转；
3. 验证描述头、字节率、有效点率和完整圈速；
4. 将 RK3588 点云与同一环境下的笔记本上位机截图对照；
5. 清空检测区，连续建立 12 圈基准；
6. 放入与移除物块，分别验证连续 3 圈后的稳定状态；
7. 退出模块后确认读取线程和串口均释放；
8. 验证机械臂与其他现有功能未被修改或自动触发。

## 不在本次范围内

- 运行或复刻官方 Windows 上位机完整工具栏；
- SLAM、目标分类、目标跟踪或摄像头识别；
- 自动控制机械臂搬运；
- 修改现有机械臂、语音、视觉模块行为；
- 在原始协议方案完成真实验证前引入 Slamtec C++ SDK。
