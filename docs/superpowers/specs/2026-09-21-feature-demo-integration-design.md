# 人工智能试验箱“功能演示”整合设计

日期：2026-09-21
目标设备：RK3588，Ubuntu 22.04，`aarch64`
目标软件名称：功能演示

## 1. 背景与目标

当前 RK3588 上的演示功能以多个独立桌面入口、Tk 窗口和 WebView 页面存在。各功能可以分别启动，但没有统一入口，也没有跨功能的生命周期管理。机械臂服务当前随系统启动并长期持有串口；不同视觉功能分别打开同一个双目摄像头；部分窗口关闭时没有等待后台线程或确认硬件已经释放。

本次改造不增加新的 AI 能力，不替换模型，不改写已经可用的识别算法和硬件控制协议。目标是将现有功能融合为一个名为“功能演示”的软件，形成以下固定流程：

> 选择功能 -> 启动功能 -> 进行演示 -> 退出功能 -> 停止后台任务并释放资源 -> 返回主界面

用户始终只看到一个软件窗口。原有程序作为算法和设备逻辑来源，不再以多个独立窗口作为最终产品入口。

### 2.2 不作为独立模块的能力

- “摄像头画面”不作为首页模块。实时画面直接出现在各视觉功能页中。
- “云台控制”不作为首页模块。云台控制并入视觉功能页。
- 视觉功能只提供云台上、下、左、右方向的步进控制。
- 不提供云台回中按钮。
- 不添加“深度学习”“数据处理”“编程实践”“更多功能”等参考图中的示例功能。

### 2.3 中文化范围

设备系统区域设置已经是 `zh_CN.UTF-8`，无需再次修改操作系统语言。需要恢复中文的是产品层：

- 唯一桌面入口名称和说明；
- 统一主界面和 13 个功能页面；
- 状态、错误、确认框和操作提示；
- 当前仍使用英文的 Tk/HTML 文案；
- 语音识别语言配置，包括当前 `VOICE_LANGUAGE=en` 覆盖项；
- AI 对话助手的系统提示、角色名称和语音反馈文案。

## 3. 选定架构

采用“统一可见主程序 + 独立功能 Worker 适配器”。

```text
功能演示（唯一 PyWebView 窗口）
  |
  +-- 统一 HTML/CSS/JavaScript 前端
  |     +-- 功能选择首页
  |     +-- 13 个功能演示页面
  |     +-- 启动、停止、错误和确认状态
  |
  +-- FastAPI 控制层
        +-- ModuleRegistry
        +-- ModuleManager（唯一 activeModule）
        +-- 功能 API、状态流和画面流
        +-- Worker 进程监督与资源验证
              +-- 视觉 Worker
              +-- 语音 Worker
              +-- 机械臂 Worker/服务
              +-- AI 对话 Worker
```

继续使用设备已有的 Python、FastAPI、HTML/CSS/JavaScript 和 PyWebView 技术，不引入 Node，不迁移框架。最终只有一个可见窗口；Worker 不创建独立 Tk 或 WebView 窗口。

现有算法逐步提取为无界面的 Worker 或适配器。提取时保持模型文件、阈值、识别流程、机械臂动作和串口协议不变，只把输入、状态、命令和清理接入统一接口。

## 4. 模块契约

每个模块通过统一契约接入：

```python
class DemoModule:
    module_id: str
    module_name: str

    def start(self) -> ModuleStatus: ...
    def status(self) -> ModuleStatus: ...
    def command(self, name: str, payload: dict) -> CommandResult: ...
    def stop(self) -> StopResult: ...
    def cleanup(self) -> CleanupResult: ...
    def verify_released(self) -> ReleaseReport: ...
```

`ModuleRegistry` 保存卡片信息、功能说明、硬件声明、Worker 类型和允许的命令。模块状态固定为：

- `idle`：未启动，不占用业务资源；
- `starting`：正在加载模型或连接设备；
- `running`：可正常演示；
- `stopping`：正在停止任务和释放资源；
- `failed`：启动或运行失败；
- `cleanup_failed`：资源未能确认释放。

`activeModule` 只能是一个模块 ID 或 `null`。开始另一个模块前，必须确认当前值为 `null` 且上一模块的释放报告通过。

## 5. 启动与退出生命周期

### 5.1 软件启动

1. 启动统一控制层和唯一 PyWebView 窗口。
2. 加载模块注册信息，不加载业务模型。
3. 不打开摄像头、麦克风、机械臂串口或云台串口。
4. 不启动识别、推理、播放或机械臂动作。
5. 首页显示 13 个功能卡片。

### 5.2 功能启动

1. ModuleManager 获取跨进程全局锁。
2. 检查 `activeModule is null`。
3. 将目标模块置为 `starting`，前端显示“正在启动功能…”。
4. 创建该模块 Worker，按需加载模型并打开必要设备。
5. Worker 完成健康检查后置为 `running`。
6. 前端显示“功能已准备就绪”并启用操作控件。
7. 任一步失败都立即执行该模块的停止和清理流程。

### 5.3 功能退出

1. 前端禁用新的操作命令。
2. 若功能正在运行，显示“退出当前功能？”确认框。
3. ModuleManager 将模块置为 `stopping`。
4. 停止识别、推理、播放和机械臂动作。
5. 通知循环、线程和定时任务退出并在限时内等待结束。
6. 终止并回收该模块创建的子进程。
7. 释放摄像头、麦克风、扬声器播放、机械臂串口和云台串口。
8. 清理临时状态、帧缓存、命令队列和客户端连接。
9. 执行资源释放验证。
10. 验证通过后令 `activeModule = null`，释放全局锁并返回首页。

### 5.4 超时与强制清理

每个步骤使用明确超时。正常停止超时后，ModuleManager 只终止该模块登记的 Worker 进程组，不使用可能误杀其他程序的宽泛命令。随后再次验证资源：

- Worker PID 和子进程均不存在；
- `/dev/video41` 无该模块持有者；
- 麦克风 PCM 设备无该模块持有者；
- `/dev/esp32_arm` 机械臂串口已关闭；
- 云台串口已关闭；
- 该模块的状态流和画面流连接已关闭。

如果二次验证仍失败，将状态置为 `cleanup_failed`，禁止启动其他模块，并显示具体的中文资源名称和恢复建议。

## 6. 机械臂服务调整

当前 `robot-arm.service` 开机启动 FastAPI，并在 `server.start()` 中连接机械臂串口和执行直立动作。这不符合首页零资源占用要求。

整合后：

- 统一主程序自身可以常驻，但不连接机械臂；
- 机械臂控制能力仅在物体分拣、按钮控制机械臂或语音控制机械臂启动时按需创建；
- 退出模块时停止当前动作和语音监听，断开 `/dev/esp32_arm`，再结束对应 Worker；
- 不再由独立的常驻业务服务在开机时占用机械臂串口；
- 不删除已有机械臂 API，而是由统一控制层内部复用或兼容调用。

## 7. 视觉模块与云台

八个视觉模块为物体分拣、车牌识别、手掌与手势识别、手掌跟踪、水果识别、颜色识别、人脸检测和形状识别。

每个视觉页包含：

- 实时摄像头画面；
- 识别框、分类或检测结果；
- 当前摄像头、模型和运行状态；
- 与原功能相符的开始、暂停、保存或动作按钮；
- 云台上、下、左、右步进按钮；
- 步进量控制使用项目现有安全范围；
- 不提供回中按钮。

视觉模块共用相同的摄像头输出和云台命令接口，但同一时间只会有一个视觉 Worker。退出时先停止识别和画面循环，再释放摄像头，最后断开云台串口。

手掌跟踪保留自动跟踪逻辑。手动方向步进与自动跟踪互斥：用户执行手动步进时暂停自动跟踪，避免两个控制源同时写云台串口。

## 8. 前端信息架构与视觉规范

### 8.1 整体框架

参考用户提供的效果图，但不复制其中超出范围的菜单和功能。界面使用白色、浅蓝色和少量模块辅助色，面向学校教学和实验室展示，不做企业后台或深色控制中心。

- 左侧导航只保留“功能演示”；
- 顶部显示“AI 试验箱”和当前页面名称；
- 首页标题固定为“功能演示”；
- 简洁横幅使用 AI 实验箱或教育机器人视觉元素，不遮挡卡片；
- 首页直接展示全部 13 个真实模块，不显示占位模块；
- 中文字体优先使用设备已有且清晰可读的中文字体；
- 卡片圆角不超过 8px，使用清晰边界和克制阴影；
- 主按钮使用蓝色，危险停止和退出操作使用明确但不过度醒目的警示色。

### 8.2 首页卡片

每张卡片包含图标、中文功能名称、一句具体说明和“开始演示”按钮。卡片本身不启动硬件；只有用户执行开始命令后才进入启动状态。

### 8.3 功能页

功能页保持统一外壳：

- 顶部提供醒目的“退出功能”；
- 左侧为功能名称、说明、步骤和资源状态；
- 右侧为真实演示内容；
- 操作按钮、状态标签、加载、空状态、成功和错误提示统一；
- 识别画面有稳定尺寸约束，不因文字或识别结果变化而跳动；
- 所有可交互控件有悬停、按下、键盘焦点和禁用状态。

### 8.4 响应式目标

优先验证：

- `1366x768`；
- `1600x900`；
- `1920x1080`。

上述分辨率下不得出现页面级横向滚动、主要按钮遮挡、文字溢出或状态覆盖画面。较低高度时允许主内容区域纵向滚动，但顶部退出入口保持可见。

## 9. API 与状态通信

统一控制层至少提供：

- `GET /api/modules`：模块列表和可用状态；
- `GET /api/modules/active`：当前模块和生命周期状态；
- `POST /api/modules/{id}/start`：启动指定模块；
- `POST /api/modules/{id}/stop`：停止并清理指定模块；
- `POST /api/modules/{id}/commands/{command}`：功能操作；
- `GET /api/modules/{id}/status`：功能状态；
- `GET /api/modules/{id}/frame`：视觉模块画面流或最新帧；
- `WS /ws/modules/{id}`：低频状态和识别结果推送。

开始和停止接口必须幂等。重复停止已停止模块返回成功；重复启动当前运行模块返回当前状态；尝试启动其他模块时返回明确冲突，不隐式并行运行。

## 10. 失败处理

- 设备缺失：指出缺失的摄像头、麦克风、机械臂或云台，不显示原始堆栈。
- 模型加载失败：显示“功能启动失败”，保留可诊断日志，并允许返回首页。
- Worker 异常退出：ModuleManager 立即进入清理流程，前端显示中断原因。
- 命令失败：保持功能页面可用，显示就地错误，不使用浏览器 `alert()`。
- 停止失败：不提前返回首页，不清空 `activeModule`，防止资源冲突。
- 主窗口关闭：执行当前模块的全局停止和清理，再退出主程序。

## 11. 部署与桌面入口

- 新增唯一桌面入口“功能演示”；
- 统一入口启动控制层和单个 PyWebView 窗口；
- 原 14 个桌面入口不再作为学生使用入口；
- 独立摄像头和独立云台入口不进入新软件；
- 部署前保留设备端现有文件的可恢复备份；
- 先在本地版本库完成和验证，再增量部署到 `192.168.11.106`；
- 不在开发过程中删除模型、历史 API 或硬件控制实现。

## 12. 测试与验收

### 12.1 自动化测试

- ModuleRegistry 精确包含 13 个模块；
- `activeModule` 互斥和跨进程锁；
- 启动成功、启动失败、停止成功、停止超时和强制清理；
- 每个适配器的命令映射和资源释放报告；
- API 幂等、冲突响应和错误中文化；
- 前端首页不触发任何业务启动 API；
- 功能页退出必须等待服务端清理完成。

### 12.2 设备验证

逐个验证 13 个模块：启动、主要操作、退出、资源释放。重点执行：

1. 语音控制机械臂 -> 退出 -> 水果识别；
2. 人脸检测 -> 退出 -> 物体分拣；
3. AI 对话助手 -> 退出 -> 语音儿歌播放；
4. 任一视觉模块 -> 退出 -> 另一视觉模块；
5. 功能运行中关闭主窗口；
6. 摄像头、麦克风、机械臂或云台断开时启动；
7. 连续切换模块至少 20 轮，观察 CPU、内存和设备持有者。

每次退出后确认没有遗留 Worker、模型推理循环、音频播放进程、摄像头持有者、麦克风持有者或串口持有者。

### 12.3 前端验证

使用真实浏览器或 PyWebView 对 `1366x768`、`1600x900`、`1920x1080` 截图检查：

- 首页 13 个功能入口可达；
- 功能页退出入口始终可见；
- 文字不溢出、不遮挡；
- 摄像头画面非空且比例稳定；
- 启动、运行、停止、失败和清理状态均可辨识；
- 不出现独立摄像头或独立云台模块；
- 视觉页只有四向云台步进控制，没有回中按钮。

## 13. 实施顺序

采用渐进式重构：

1. 建立统一应用外壳、模块注册表和 ModuleManager；
2. 建立生命周期测试与设备资源验证器；
3. 接入一个低风险视觉模块，验证单窗口画面与退出流程；
4. 接入其余视觉模块和四向云台步进；
5. 接入机械臂相关模块并取消开机业务串口占用；
6. 接入语音和 AI 对话模块；
7. 完成全部中文化和统一前端；
8. 完成跨模块切换、异常退出、资源释放和分辨率验收；
9. 备份设备当前版本后增量部署，保留回滚路径。

## 14. 验收结论

只有同时满足以下条件才视为完成：

- 设备桌面只需通过“功能演示”进入产品；
- 单一窗口中可使用全部 13 个现有功能；
- 首页不占用摄像头、麦克风、机械臂或云台；
- 任意时刻只有一个活动模块；
- 退出模块后资源释放得到服务端确认；
- 视觉模块包含实时画面和四向云台步进，不含回中；
- 摄像头画面和云台控制不作为独立模块；
- 所有面向学生的文案和语音行为恢复为中文；
- 三种目标分辨率下界面稳定可用；
- 原有识别算法、模型和硬件动作行为没有功能回退。
